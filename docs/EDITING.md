# Редактирование сайта

## Основные тексты и контакты

Редактируйте `content/locales.json`: один и тот же ключ должен существовать в RU, LT и EN. Контактные данные, домен и реквизиты находятся в `content/settings.json`: там же настоятель (`rector`), WhatsApp, соцсети (`social`), время открытия храма (`openFrom`), автобусы и остановка (`transport`), адрес формы записок (`notes`) и ID приходского Google-календаря (`calendarId`) для подписки. Эти сведения взяты с bukiski-hram.net 11 октября 2026 г.; источник каждого блока указан в поле `source`. Сначала измените файл, затем выполните `npm run check` и откройте изменённые страницы через `npm run dev`.

Языки сайта не обозначают языки богослужений. Не добавляйте обещания богослужения на LT/EN без подтверждения прихода. Литовский текст подготовлен редакционно, профессиональная вычитка носителем языка и священником пока не выполнена.

Рабочие термины: «Божественная литургия» → «Dieviškoji liturgija» → «Divine Liturgy»; «О здравии» → «Už gyvuosius» → «For the living»; «Об упокоении» → «Už mirusiuosius» → «For the departed». Для сложных церковных терминов необходимо согласование, а не механическая замена слов.

## Расписание

Текущий источник — `content/original-services.json`. Перед изменением времени получить подтверждение ответственного за приходской календарь. Пример структуры события:

```json
{
  "id": "stable-parish-event-id",
  "date": "2026-10-11",
  "startTime": "08:00",
  "start": "2026-10-11T05:00:00.000Z",
  "source": "parish-calendar",
  "allDay": false,
  "timePending": false,
  "title": {
    "ru": "Божественная литургия",
    "lt": "Dieviškoji liturgija",
    "en": "Divine Liturgy"
  }
}
```

В примере используется реальная запись исходного снимка. Не копируйте её дату для новой службы. `start` должен соответствовать местному времени Вильнюса на конкретную дату, включая сезонное смещение. При отмене сохраняйте ID и задавайте `status: cancelled`. Не меняйте автоматически дату последнего успешного обновления: она должна отражать проверенный источник.

Для импорта проверенного локального файла:

```sh
node scripts/sync-schedule.mjs /absolute/path/to/reviewed-services.json
npm run check
```

Для внешнего источника задайте `SCHEDULE_SOURCE_URL` в окружении и выполните `npm run schedule:sync`. По умолчанию сетевой источник не выбирается: после переноса `.org` нельзя создавать цикл, читая собственную опубликованную копию. Импорт сохраняет timestamp исходного календаря. Неудача оставляет последнюю рабочую версию.

Тестовая публикация делает это сама каждые шесть часов: workflow «Deploy test preview to GitHub Pages» загружает снимок из адреса в переменной репозитория `SCHEDULE_SOURCE_URL` (по умолчанию `https://bukiski-hram.org/data/services.json`), проверяет его и публикует сайт. Файл в репозитории при этом не меняется: он остаётся запасным снимком на случай недоступности источника при ручной публикации. Порог предупреждения об устаревшем расписании задаёт `scheduleMaxAgeHours` в `content/settings.json`.

## Статьи и архив

Исходные записи находятся в `source-pages.json`. Не переписывайте архив задним числом: он предназначен для проверки переноса. У записи есть исходный URL, язык, описание, блоки текста и изображения. Чтобы добавить новую редакционную статью в текущую небольшую систему, добавьте запись с собственным постоянным URL в это хранилище и отметьте её источник; при развитии проекта разумно выделить новые публикации в отдельную коллекцию, оставив импорт неизменным.

Изменение опубликованного slug требует обновления явного соответствия в сборщике и проверки migration.csv. Изменение только заголовка не должно менять URL. HTML из конструктора никогда не вставляется в страницу напрямую.

Текстовые блоки показываются по типам: `p` — абзац, `h1`–`h6` — заголовки, подряд идущие `li` — список, `dt`/`dd` — список определений, `blockquote` — цитата. Короткие нумерованные абзацы вида «1. Название раздела» показываются как заголовки, если их в статье не меньше двух, они не заканчиваются точкой и не идут подряд (подряд идущие нумерованные строки — это список). Текст при этом не меняется. Точное правило — в `scripts/lib/pages/article.mjs`.

## Фотографии

Все фотографии описаны в `content/photos.json`:

- `hero` — снимок храма на главной в трёх размерах (960, 1600 и 2400 px по ширине); браузер сам выбирает подходящий;
- `gallery` — снимки страницы «Фотографии» в порядке показа: файл для просмотра на весь экран (`web`), уменьшенная копия (`thumb`), их размеры, источник и подписи на трёх языках;
- `homeMosaic` — какие снимки галереи (по `id`) показать на главной в разделе «Фотографии»; первый выводится крупно.

Чтобы добавить снимок, сохраните его в `assets/img/parish/` в WebP (длинная сторона около 1600 px) и уменьшенную копию `-thumb.webp` (около 640 px), затем добавьте запись в `gallery` с настоящими размерами файлов и подписями. Сборка остановится, если `homeMosaic` ссылается на отсутствующий снимок. На снимках, где узнаваемы прихожане, нужно их согласие на публикацию. Изображения, созданные нейросетью, в галерею не включаются.

## Изображения

Страницы используют WebP-копии из `assets/img/web/` и размеры из `content/image-manifest.json`. После добавления или замены исходного изображения выполните `npm run images:optimize` (нужны Python 3 и Pillow) и закоммитьте новые файлы вместе с манифестом. Первая широкая картинка статьи становится обложкой и миниатюрой в библиотеке; несколько кадрировок одной фотографии сводятся к самой крупной; маленькие изображения не растягиваются.

## Стили и интерфейс

Стили лежат в `styles/` и собираются в один файл по алфавиту имён: переменные темы, основа, каркас, компоненты, страницы, доступность, печать. Цвета меняются в `00-tokens.css`; тёмная тема записана там дважды (по системной настройке и по выбору посетителя), тест следит, чтобы копии совпадали. Новые подписи интерфейса добавляются в `content/locales.json` сразу на трёх языках и передаются клиентскому коду через `data-`атрибуты разметки.

Все четыре исходных документа восстановлены. Файлы находятся в `assets/documents/`, а их источники, размеры и SHA-256 — в `content/source-documents.json`. При согласованной замене файла обновите реестр и выполните `npm run check`: проверка подтверждает неизменность байтов в HTML-страницах загрузки, отсутствие прямых PDF/DOC в сборке и ссылки в статье, архиве и совместимом старом адресе. В режиме `envelope` не копируйте исходную папку `assets/documents/` поверх сборки: это вернёт индексируемые адреса. Не заменяйте оригинал похожим материалом без явной пометки.

## Проверки

`npm run check` собирает сайт и запускает 48 проверок: сохранность текста и ссылок, структура статей и размеры изображений, SEO-структура, языковые эквиваленты, экранирование, схема календаря, отмены, DST, свежесть, ICS, проверка имён, правила клиентского кода, контраст цветов светлой и тёмной темы и минимальный размер текста. В CI проверка выполняется дважды — для обоих режимов выдачи документов — и дополнительно убеждается, что `deploy/old-domain.htaccess` и `content/migration.*` в репозитории соответствуют содержимому. Дополнительно вручную проверяйте внешний вид изменённых страниц, клавиатуру, мобильный экран, масштаб текста и печать. Проверка кода не заменяет богословскую вычитку, тест экранным диктором или юридическую оценку.

## Иллюстрированная история храма

Статья «История о храме» (`/ru/library/istoriya-o-hrame.html`) показывается в отдельном оформлении: главы, карточки, хронология, сравнение «было и стало» и фотографии храма до восстановления. Порядок и группировка текста описаны в `content/stories/istoriya-o-hrame.json`; каждая фраза там дословно взята из сохранённой страницы, и тесты проверяют это совпадение. Пропускать можно только декоративные значки из списка `decorative`. Фотографии до восстановления лежат в `assets/img/restoration/`, подписи — в разделе `restoration.photos`.

## Языки сайта

Сайт работает на шести языках: русский, литовский, английский, польский, немецкий и украинский. Тексты интерфейса — в `content/locales.json`; у всех языков одинаковый набор ключей, это проверяет сборка. Названия служб и дней церковного календаря приходят из приходского календаря на русском, литовском, английском и польском; немецкие и украинские названия (и польские — если календарь их не дал) берутся из `content/liturgical-terms.json`. Если в календаре появится новое название без перевода, сборка покажет предупреждение и временно выведет английский вариант — допишите перевод в этот файл. Переводы на польский, немецкий и украинский требуют проверки носителем языка и священником (`translationReview` в `content/settings.json`).

## Служба, которой ещё нет в календаре

Если служба подтверждена, а в приходском Google-календаре её нет или она стоит без времени, её можно добавить в `content/schedule-additions.json`: дата, время по Вильнюсу, название службы, название дня и (по желанию) пояснение — на всех шести языках. Сайт покажет её в расписании, на главной и в файле календаря. Когда служба с тем же днём и временем появится в календаре, сайт возьмёт её оттуда и сохранит только пояснение; запись после этого можно удалить.

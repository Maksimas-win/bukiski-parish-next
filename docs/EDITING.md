# Редактирование сайта

## Основные тексты и контакты

Редактируйте `content/locales.json`: один и тот же ключ должен существовать в RU, LT и EN. Контактные данные, домен и реквизиты находятся в `content/settings.json`. Сначала измените файл, затем выполните `npm run check` и откройте изменённые страницы через `npm run dev`.

Языки сайта не обозначают языки богослужений. Не добавляйте обещания богослужения на LT/EN без подтверждения прихода. Литовский текст подготовлен редакционно, профессиональная вычитка носителем языка и священником пока не выполнена.

Рабочие термины: «Божественная литургия» → «Dieviškoji liturgija» → «Divine Liturgy»; «О здравии» → «Už gyvuosius» → «For the living»; «Об упокоении» → «Už mirusiuosius» → «For the departed». Для сложных церковных терминов необходимо согласование, а не механическая замена слов.

## Расписание

Текущий источник — `content/original-services.json`. Перед изменением времени получить подтверждение ответственного за приходской календарь. Пример структуры события:

```json
{
  "id": "stable-parish-event-id",
  "date": "2026-10-11",
  "startTime": "08:00",
  "start": "2026-10-11T05:00:00.000Z",
  "source": "parish-calendar",
  "allDay": false,
  "timePending": false,
  "title": {
    "ru": "Божественная литургия",
    "lt": "Dieviškoji liturgija",
    "en": "Divine Liturgy"
  }
}
```

В примере используется реальная запись исходного снимка. Не копируйте её дату для новой службы. `start` должен соответствовать местному времени Вильнюса на конкретную дату, включая сезонное смещение. При отмене сохраняйте ID и задавайте `status: cancelled`. Не меняйте автоматически дату последнего успешного обновления: она должна отражать проверенный источник.

Для импорта проверенного локального файла:

```sh
node scripts/sync-schedule.mjs /absolute/path/to/reviewed-services.json
npm run check
```

Для внешнего источника задайте `SCHEDULE_SOURCE_URL` в окружении и выполните `npm run schedule:sync`. По умолчанию сетевой источник не выбирается: после переноса `.org` нельзя создавать цикл, читая собственную опубликованную копию. Импорт сохраняет timestamp исходного календаря. Неудача оставляет последнюю рабочую версию.

## Статьи и архив

Исходные записи находятся в `source-pages.json`. Не переписывайте архив задним числом: он предназначен для проверки переноса. У записи есть исходный URL, язык, описание, блоки текста и изображения. Чтобы добавить новую редакционную статью в текущую небольшую систему, добавьте запись с собственным постоянным URL в это хранилище и отметьте её источник; при развитии проекта разумно выделить новые публикации в отдельную коллекцию, оставив импорт неизменным.

Изменение опубликованного slug требует обновления явного соответствия в сборщике и проверки migration.csv. Изменение только заголовка не должно менять URL. HTML из конструктора никогда не вставляется в страницу напрямую.

Для восстановления недоступного документа: положите полученный у владельца файл в `assets/documents/`, укажите его путь в соответствующей записи `content/source-documents.json` и повторите сборку. В статье исходная ссылка будет заменена локальной.

## Проверки

`npm run check` собирает сайт и запускает 18 проверок: сохранность текста и ссылок, SEO-структура, языковые эквиваленты, XSS, схема календаря, отмены, DST, свежесть, ICS, валидация имён и контраст основных текстовых цветов. Дополнительно вручную проверяйте внешний вид изменённых страниц, клавиатуру, мобильный экран, масштаб текста и печать. Проверка кода не заменяет богословскую вычитку, тест экранным диктором или юридическую оценку.
